# Decisions

Append-only. Each entry: id, date, decision, why, consequences.

## D-001 (2026-11-21) Rust + DataFusion + Parquet, single binary
**Why:** lean self-hosting (one process, one volume) with columnar analytics performance. **Consequences:** funnels, retention and paths are written as DataFusion aggregate functions, and there is no external database.

## D-002 (2026-11-21) Licence AGPL-3.0-only; dependencies limited to a permissive allowlist
**Why:** self-hosters are free; anyone hosting a modified version must publish it. Dependencies stay permissive so that combining them is never in doubt. **Consequences:** `deny.toml` enforces the allowlist, and MPL-2.0 is allowed only per crate and unmodified.

## D-003 (2026-11-21) Rust everywhere except the browser SDK
**Why:** the SDK runs inside the customer's own pages. It must be tiny, needs no WebAssembly, and session recording relies on the rrweb recorder (MIT). **Consequences:** `sdk/js` is TypeScript, kept under 10 kB gzipped without replay. All other code, including the UI (Leptos), is Rust.

## D-004 (2026-11-21) Roles and features are first-class concepts
**Why:** the main users are PMs who ask "which roles use which features". **Consequences:** `identify()` takes `role`/`account`/`plan`. These are promoted to columns and copied onto events at capture time. The feature catalog lives in `meta`, and the default dashboard is the roles × features matrix (M3).

## D-005 (2026-11-21) Agent wiring returns plans, not free-form edits
**Why:** "add one dependency and let an agent wire it" only scales if every edit can be reviewed and verified. **Consequences:** `crates/wire` outputs a typed install plan, applied by `openlens-cli wire` or returned through MCP. `openlens-cli verify` closes the loop.

## D-006 (2026-11-21) The feature map is an explicit file that agents maintain in the app repo
**Why:** most target apps are vibecoded or maintained by agents. Features inferred from clicks are noisy, while a declared map (entry points, success event, steps) is precise, can be reviewed in PRs, and is cheap for agents to keep current. **Consequences:** `openlens.features.yaml` has a JSON Schema, `features push` / `features lint`, a rules snippet injected into the app's AGENTS.md, and versioned feature keys on the server.

## D-007 (2026-11-21) Simple UI, deep agent access
**Why:** PMs want patterns ("what makes users stick", "where they churn", "which journeys create value"), not a query builder. Agents can do the deep analysis if given clean data. **Consequences:** the UI is limited to three questions plus drill-down. Every analysis is also an MCP tool returning a compact summary with drill-down ids. Raw data is exported as Parquet/JSONL with a stable documented schema, and read-only SQL is exposed to agents.

## D-008 (2026-11-21) Home screen is the Focus board, an insights feed rather than a builder
**Why:** a PM opening OpenLens wants to know where the value is and what to focus on, not to build charts. **Consequences:** M3 ships ranked, evidence-backed insight cards generated by engine commands (the same ones agents call through MCP). The empty state is honest about missing data and wiring gaps. Any LLM wording pass is optional and cannot alter the numbers.

## D-009 (2026-11-21) Roles are declared and matched in the feature map, and history-aware
**Why:** role is the key dimension for every KPI. Free-text roles sent by apps drift (`owner`, `Admin`, `superadmin`). **Consequences:** canonical roles plus match rules live in `roles:`; raw values are kept; unmatched values raise role-gap cards; role changes are stored with their date, and events carry the role the user had at event time.

## D-010 (2026-11-21) KPI catalog with fixed definitions; errors and Web Vitals move to M1
**Why:** Phil's key KPIs cover users (DAU/MAU, churn, session duration, tasks), performance (errors, CWV) and features (most/least used, longest tasks), all split by role. **Consequences:** `docs/kpis.md` is the contract for the UI, MCP and exports. A "task" is formally a feature entry → success event. Basic error capture and CWV ship in the M1 SDK, while M7 keeps deep grouping and source maps.
