# 🔭 OpenLens v0.1.0

**Product analytics as a method, not a toolbox.** This is the first release of OpenLens: self-hosted product analytics in one Rust binary. Your coding agent wires it into an app, and your PM opens a board that already says where the value is.

## ✨ Highlights

- 🎯 **A populated Focus board on the first login.** Ranked insight cards, each with its evidence, its cohort size and a next step:
  - what makes users stick, and where they churn;
  - role blind spots;
  - release regressions, slow pages, funnel drops;
  - flag wins, with significance tests.
- 👥 **Every KPI by role, account, plan, environment and release.** The definitions are fixed and documented in [docs/kpis.md](../kpis.md), and audited against the code for this release.
- 🤖 **Zero human setup.** `openlens-cli` and an MCP server let an agent do everything:
  - create the project and draft the feature map;
  - backfill history;
  - verify the wiring;
  - hand over a login link.
  - The agent guide (served at `/agents.md`) has recipes for Next.js, Nuxt, SvelteKit, Astro, Remix and server-rendered apps.
- 🔌 **One small SDK** (4.6 kB gzipped).
  - **Captured on its own:** page views, clicks named by `data-feature` (also inside web components), errors, Web Vitals and failed requests.
  - **Privacy:** no cookies, inputs never captured.
  - **Replay:** loads lazily, with inputs masked.
- 🚩 **Act on it:** feature flags (each one becomes a cohort on the board), in-app micro-surveys and a weekly digest.
- 🪶 **Lean.** One binary, Parquet files you own, about 80k events/s on one vCPU, no required configuration.

## 🚀 Install

**Docker:**

```sh
docker run -d -p 8686:8686 -v openlens-data:/data ghcr.io/philippe-arnd/openlens:v0.1.0
# the admin token is printed in the logs on first start
```

**Coolify:** use the one-click template in [docs/deploy/coolify.md](../deploy/coolify.md). Coolify generates the admin token and the URL. On the first login, OpenLens asks for your email and creates your admin account.

**Wire an app:** point your coding agent at `https://<your-openlens>/agents.md`, or by hand:

```html
<script src="https://<your-openlens>/c.js" data-key="pk_…" data-release="<git sha>" defer></script>
<script>addEventListener("DOMContentLoaded", () => openlens.identify(USER_ID, { role: USER_ROLE }));</script>
```

**Optional features** stay off until their environment variables are set ([docs/deploy/coolify.md](../deploy/coolify.md)):
- the SMTP weekly email;
- LLM rewording of cards;
- OpenID Connect single sign-on;
- an S3 copy of the data.

## ⚠️ Breaking changes

None for a new install. Instances that ran pre-release builds should note four changes:
- **SQL:** `events` is now a view that gives each user the events sent before login. The stored rows are in `raw_events`.
- **User counts:** DAU/WAU/MAU, retention and cohorts count identified users only. Visitors who never logged in are shown apart.
- **Script tag:** the server defaults to the directory `c.js` came from, path included. The URL is unchanged for `https://lens.example.com/c.js`.
- **`reset()`** does nothing while nobody is identified.

The data on disk is compatible, and nothing needs to be migrated by hand.

## 🧭 Known limitations

- **One node:** a single process with local disk. The S3 copy is a backup, not shared storage.
- **npm:** `@openlens/web` is not on npm yet (the repository is still private). Use the script tag or a `file:` dependency. Publishing is ready in `.github/workflows/npm.yml`.
- **Web only:** there is no native mobile SDK (iOS, Android, React Native, Flutter). Server events go through the Node or Python SDK, or `POST /capture`.
- **Small samples:** insight cards wait for 8 or more users per compared group, so a small app shows KPIs before it shows cards.
- **Days are UTC days** in every KPI.
- **Rare duplicates:** a send that reached the server but whose answer was lost is sent again. That is rare, and it can duplicate those few events.
- **Form submits inside shadow roots** are not captured yet. Clicks inside them are.
- **Dogfooding is ongoing (M6):** two production apps since 2026-11-22. The exit check is 30 days without data loss.
