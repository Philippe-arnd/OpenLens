# 🔭 OpenLens v0.3.0

**From a dashboard to a product team's daily tool, measured at scale and locked down.** v0.3.0 adds the views a PM opens every day (churn, goals, acquisition, flows, live, uptime, Ask), turns findings into tickets with a measured effect, and spends the rest on trust: access checked by type, SQL values bound, a versioned API, daily rollups that outlive raw events, and numbers measured at 63 M events.

## ⚠️ Upgrade now if you run v0.2.0

- **Flag and survey edit pages were readable without signing in** (#294). Every `/p/…` page now refuses anonymous visitors in one place, and a test walks every route.
- **A login link could be used up by a link preview** (Slack, Teams, Outlook Safe Links) before the person opened it (#315). Opening a link now shows a *Continue* button, and only that POST uses it.
- **The admin token appeared in the first-start log** and was stored in clear. It is now stored hashed, and the first start prints a one-time owner link instead (#342).

## 🔒 Security

v0.3.0 fixes three vulnerabilities reported privately during the showcase audit. Every version before 0.3.0 is affected; 0.3.0 is patched.

- **Ask's SQL tool returned person-level data when person-level detail was off** (SEC-01, [GHSA-p52g-xmcm-2wrj](https://github.com/Philippe-arnd/OpenLens/security/advisories/GHSA-p52g-xmcm-2wrj), high). Ask now queries an aggregate-only view where people are pseudonyms and groups under 5 people are dropped (D-021).
- **The admin token was stored in plaintext**, reused as the session signing key and copied into backups (SEC-02, [GHSA-v4mh-3vr2-7mxf](https://github.com/Philippe-arnd/OpenLens/security/advisories/GHSA-v4mh-3vr2-7mxf), high). It is stored hashed, and sessions use their own key.
- **The ingestion rate limit applied only to requests carrying `X-Forwarded-For`**, and the replay endpoint had none (SEC-03, [GHSA-f5h9-73gg-3vhv](https://github.com/Philippe-arnd/OpenLens/security/advisories/GHSA-f5h9-73gg-3vhv), medium). Clients are now identified by their connection address, and the header is trusted only from private and loopback proxies (D-022).

## ✨ Highlights

- 📉 **Churn, goals and acquisition.** Why users leave and who came back, goals on KPIs with a 30-day pace, channels grouped by themselves (search, social, email, AI assistants…).
- 🧭 **Feature flow, live view, timeline.** How sessions move between features, who is here now, and every release, flag change and note on one timeline.
- 🩺 **Is the app down?** Uptime checks every minute, TLS expiry, regression and error-spike alerts, with quiet hours.
- 🤖 **Ask OpenLens.** An AI chat on every project that answers from the board and from SQL, shows its evidence, and only *proposes* changes. Off until an admin sets a model; without person-level detail it reads an aggregate-only view.
- 🎫 **From finding to ticket to effect.** A card becomes a GitHub issue, and the board reports what changed once the fix shipped.
- 🧪 **Experiments.** Flags with 2–6 weighted variants and a readout per arm, plus targeting by plan, country or any property.
- 🔁 **Daily rollups.** Every closed day is rolled up (people, metrics, click maps, scroll depth), in 15-minute buckets so any time zone gets its own days. Rollups are kept after the raw events expire, so older periods can still be compared.
- 🔐 **Access and SQL, by construction.** Every page and API route states its access level in its type. Filter values reach DataFusion as parameters, never as SQL text, and CI refuses a hand-made escape.
- 📜 **A versioned API.** `/api/v1/...` with an OpenAPI document at `/api/openapi.json`, kept equal to the code by a test, and stable error codes (`{"code", "message"}`). Scoped API tokens (`read`, `write`, `admin`, per project) from *Settings → API tokens*.
- ⚡ **Faster and steadier.**
  - The board page shows at once and streams its numbers.
  - Ingestion shares one `fsync` between requests.
  - Board queries run on their own threads.
  - One long free-form query runs at a time, so the board never waits.
- 🧊 **Room to grow.** With S3 set, the hourly copy holds the rollups too, and event days older than 120 days move to S3 once their copy is verified.
- 🛡️ **Privacy profiles.** Exempt (cookieless, no replay), Standard and Full are described and checked in a real browser. Clicks lose their text and position after 30 days. *Forget this person* reaches the rollups and the cold tier too.

## 🚀 Install or upgrade

```sh
docker run -d -p 8686:8686 -v openlens-data:/data ghcr.io/philippe-arnd/openlens:0.3
helm upgrade --install openlens oci://ghcr.io/philippe-arnd/charts/openlens -n openlens --create-namespace
```

**Coolify:** redeploy the template; it follows `:latest`. The first start of v0.3.0 copies the data to `backups/upgrade/`, then rolls up the history it already holds, seven days per project every ten minutes.

## ⚠️ Changes in behaviour

- **Sessions are signed with their own key** (`<data>/.session.key`), so everyone signs in again once after the upgrade.
- **The browser SDK sends less by default:** page URLs lose their query string (campaign tags are kept), and click text is kept only under `data-feature` or when it names nobody.
- **The admin token opens admin pages too**, as it already did for project changes.
- **API errors carry `code` and `message`.** `error` repeats the message for this release only.
- **Clicks older than 30 days keep only their page, time and rage flag**, once their day is rolled up.
- **With S3 set, event days older than 120 days live on S3 only.** Keep the bucket: local backups hold only the days on disk.

The data on disk is compatible, and nothing needs to be migrated by hand.

## 🧭 Known limitations

- **One node:** a single process with local disk.
- **Large apps:** past about 4 M events in 90 days the board reads files instead of memory and gets slow (22 s at 63 M on 4 vCPU). The board reading rollups comes next (#323).
- **npm:** `@openlens/web` is not on npm yet. Use the script tag or a `file:` dependency.
- **Beta:** 0.x releases may change behaviour, always announced ([docs/stability.md](../stability.md)).
