# 🔭 OpenLens v0.6.0

**A new look, releases judged for you, and uptime you can show.** v0.6.0 redraws the whole dashboard, names every release and says whether it made things better or worse, keeps 90 days of uptime with maintenance windows and an availability target, can publish a public status page, and reads the board from daily rollups so a large project opens in seconds.

## ⚠️ Upgrade now if…

- **You capture a lot of events.** Under load, capture could answer *503 cannot store events* when the metadata store was briefly locked; it now waits for the lock (#510).
- **Your board is slow to load a second time.** On large projects a board that failed was computed again on every load. A query that runs out of memory now runs once more alone, and a board that loaded is served from the cache (D-071).

## ✨ Highlights

- 🎨 **A new dashboard.** One palette for light and dark, a sidebar with a *Go to…* field and sections on keys 1–8, a top bar with the period, environment, role and release as chips, a lead insight with a before/after comparison, KPI tiles that say what they are compared with, tables grouped by day, and one explained empty state per page. Still no JavaScript and no new setting (#539–#552).
- 🧭 **Go to…** opens a section, a feature or a person by name (#541).
- 🛡️ **Destructive actions ask in a dialog**, at the end of their page, without JavaScript: forget a person, delete a flag or a project, sign out everywhere (#545).
- 🏷️ **Releases detected with no setup.** The browser SDK fingerprints each build, so releases get a name even when the app sends none (#495).
- 📦 **A Releases page** lists each release per environment as rolling out, live, superseded or rolled back, with its deploys (#500, #504).
- ⚖️ **A verdict per release**: healthy, regressed or inconclusive against the one before, from errors, bounce, completed tasks, Web Vitals, feature success and goal guardrails (#522).
- 🚀 **`openlens-cli release` and a GitHub Action** record a release from the deploy step, upload its source maps and wait for its verdict (#521). A deploy hook reads the notifications of the common hosting platforms (#504).
- 📊 **Delivery metrics**: deploy frequency, lead time, change failure rate and time to restore, per environment (#523).
- 🟢 **90 days of uptime**, every incident, availability over 24 hours to 365 days, and an availability target with its error budget and two alerts (#559, #560).
- 🛠️ **Planned maintenance windows** hold alerts and are left out of availability (#563). **Announcements** follow an incident as dated updates (#562).
- 🌐 **A public status page** at `/status/<slug>`, with a JSON version, a badge and a feed. Off by default; it never shows an address, an error text or a person (#561).
- ⏱️ **The board reads since the current release** and compares with the same length before. A date range or a past release can be picked; a long one says what it would read first and runs in the background (#323, #513–#515).
- ⚡ **A faster board.** It reads daily rollups for closed days instead of scanning 30 or 90 days of events, and no longer keeps a copy of the events in memory (#452, #502).
- 🗺️ **Environments by host.** Host rules, aliases, hidden environments, uptime checks per environment, re-labelling past events and an optional list of allowed hosts (#410, #484, #485).
- 🐢 **Web Vitals explained**: what the visitor feels, the worst pages, the element and the part that weighs most, and what to do first (#408, #467).
- 🎞️ **Replays pause when nobody is there**, and about 300 recordings a day per project are kept with no setting (#404, #327).
- 🔐 **An authenticator app for password sign-in**, and a password reset by an admin (#440, #428).
- 🤖 **Every engine command an agent may run is an MCP tool** (#525).
- 🧰 **More ways to self-host**: an ARM image, a one-command systemd install with daily updates, Nomad, NixOS, Swarm, panel recipes, and an opt-in Kubernetes auto-update (#487, #238, #198). Releases carry SLSA level 3 provenance (#473).

## 🚀 Install or upgrade

```sh
docker run -d -p 8686:8686 -v openlens-data:/data ghcr.io/philippe-arnd/openlens:0.6
helm upgrade --install openlens oci://ghcr.io/philippe-arnd/charts/openlens -n openlens --create-namespace
```

**Coolify:** the template now follows the minor channel; point it at `:0.6`. **systemd:** `curl … | sudo sh -s -- 0.6` ([guide](../deploy/systemd.md#install-in-one-command)). The first start of v0.6.0 copies the data to `backups/upgrade/`.

## ⚠️ Changes in behaviour

- **The board covers *Since vX.Y*** instead of fixed 7- and 30-day windows, compared with the same length before. Alerts, goals, the digest, Ask and shared boards keep the fixed windows, as does the API with `?window=fixed` (#323).
- **A host nothing classifies is `unknown`, not production.** On upgrade, every host that sent production events in the last 30 days keeps a production rule (#410).
- **Journeys are made of features**, a churn point is a feature, and friction counts a success the way tasks do (#452).
- **Password sign-in slows down after failures instead of locking**, so nobody can lock someone else out (#428).
- **The filters are chips in the top bar.** The URL parameters did not change (#542).
- **The Coolify template follows `:0.6`**, not `:latest` (#198).

The data on disk is compatible; new rollup tables are filled in the background.

## 🧭 Known limitations

- **One node:** a single process with local disk.
- **Heatmap:** no Mobile / Tablet / Desktop split yet (one median width is kept per page), and labels and scroll depth cover the 15 most viewed pages (#548).
- **Stylesheet:** about 23 kB compressed, above the 12 kB the new design aims for (#579).
- **Beta:** 0.x releases may change behaviour, always announced ([docs/stability.md](../stability.md)).
